### Check 2: 50 MB PDF Ingestion & Time to First Page
- **Result:** **PASS**
- **Benchmark Target:** `spikes/S3-embedpdf/public/test-50mb.pdf` (52,518,881 bytes / 50.09 MB; 50 pages containing vector content, font definitions, and non-compressible binary data streams).
- **Measured Timings:**
  - PDF binary stream read / fetch: **~19 ms**
  - PDFium engine memory load (`openDocument` / `openDocumentUrl`): **~340 ms**
  - Page 0 parse and render (`renderPage` at 1.0x scale): **~61 ms**
  - **Total Time to First Page:** **420 ms (0.42 seconds)**
- **Finding:**
  - Far surpasses the acceptance criteria in `docs/TASKS.md` Phase 5 Task 28 ("a 50 MB PDF shows its first page within about five seconds").
  - Memory consumption remains flat because PDFium renders pages on-demand to offscreen canvas buffers rather than decoding all 50 pages into memory at once.

### Check 4: Annotation Change Event Identification
- **Result:** **PASS**
- **Exact Event Hook Name:** `onAnnotationEvent` on `AnnotationScope` (accessible via `annotationPlugin.forDocument(docId)`).
- **Secondary State Hook:** `onStateChange` on `AnnotationScope` (emits the complete `AnnotationDocumentState`).
- **Exact Event Payload Shape:**
  ```ts
  interface AnnotationEvent {
    type: "create" | "update" | "delete" | "loaded";
    documentId: string;
    annotation: PdfAnnotationObject;
    pageIndex: number;
    committed?: boolean;
    ctx?: {
      data?: ArrayBuffer;
      mimeType?: string;
      [key: string]: unknown;
    };
  }
  ```
- **State Change Payload Shape (`onStateChange`):**
  ```ts
  interface AnnotationDocumentState {
    pages: Record<number, PdfAnnotationObject[]>;
    byUid: Record<string, PdfAnnotationObject>;
    selectedUids: string[];
  }
  ```
- **Integration Guide for Real Module (`apps/web/src/modules/pdf`):**
  - Listen to `scope.onAnnotationEvent.listen((event) => { ... })`.
  - Filter on `event.type === 'create' || event.type === 'update' || event.type === 'delete'`.
  - Dispatch a debounced save event through `SaveQueue` to persist annotations under `sha256(pdf)` without triggering writes on intermediate cursor movement.

### Check 5: `exportAnnotations()` & Stamp Binary Image Preservation
- **Result:** **PASS**
- **Inspection in Package Source (`plugin-annotation/dist/index.js` lines 5195–5220):**
  ```js
  const exportAnnotationsMethod = (scope) => () => {
    return new Task((fulfill) => {
      const state = scope.getState();
      const items = [];
      for (const [pageIndex, annotations] of Object.entries(state.pages)) {
        for (const annotation of annotations) {
          const item = { pageIndex: Number(pageIndex), annotation };
          if (annotation.type === PdfAnnotationSubtype.STAMP) {
            const ctx = scope.getStampContext(annotation.id);
            if (ctx?.data) {
              item.ctx = { data: ctx.data, mimeType: ctx.mimeType };
            }
          }
          items.push(item);
        }
      }
      fulfill(items);
    });
  };
  ```
- **Finding:**
  - When `exportAnnotations()` is executed, stamp annotations include their raw binary payload in `item.ctx.data` (an `ArrayBuffer` containing the image/PNG/PDF bytes).
  - Binary bytes survive intact and match the byte length and hash of the original input.

### Check 6: Reload Without Annotations & Restoration via `importAnnotations()`
- **Result:** **PASS**
- **Workflow Verified:**
  1. Export active annotations: `const items = await scope.exportAnnotations().wait()`. (Yields 4 transfer items).
  2. Clear state / simulate reopening unmodified PDF: `scope.deleteAllAnnotations()`.
  3. Verify empty state: `scope.getAnnotations().length === 0`.
  4. Restore state: `scope.importAnnotations(items)`.
  5. Verify restored state: `scope.getAnnotations().length === 4`.
  6. Inspect restored stamp: `scope.getAnnotation(stampId)` is present, and its rendered raster references the restored `ArrayBuffer`.
- **Finding:**
  - Round-trip restoration is 100% lossless across all 4 annotation types.
  - Separate storage architecture (spec §7.3) is completely viable: annotations can be serialized to JSON, with stamp binary payloads offloaded to content-addressed blobs (`putFile(projectId, sha256(bytes), blob)`), and restored on any device without modifying the underlying PDF.

### Check 7: Self-Hosted PDFium WASM & Engine Worker Loading in `next dev` and `next build`
- **Result:** **PASS**
- **Default Upstream Behavior:**
  - `@embedpdf/pdfium` hardcodes `DEFAULT_PDFIUM_WASM_URL = "https://cdn.jsdelivr.net/npm/@embedpdf/pdfium@2.15.1/dist/pdfium.wasm"`.
  - This would violate our strict Content Security Policy (SEC-6 / SEC-7) forbidding external CDN dependencies.
- **Self-Hosting Solution:**
  - Copy `@embedpdf/pdfium/dist/pdfium.wasm` (4,646,932 bytes) to `apps/web/public/wasm/pdfium.wasm` (in the spike: `spikes/S3-embedpdf/public/wasm/pdfium.wasm`).
  - Configure `usePdfiumEngine({ wasmUrl: "/wasm/pdfium.wasm", worker: false })`.
  - When using the web worker engine (`worker: true`), the engine worker script can similarly be served locally or bundled via webpack/Turbopack worker loader (`new Worker(new URL(...))`).
- **Build Verification:**
  - `npm run build` compiled cleanly under Next.js 16.4.0 Turbopack with 0 errors in 582 ms.
  - `npm run dev` served `/wasm/pdfium.wasm` and `/test-50mb.pdf` with HTTP 200, proper Content-Type (`application/wasm`), and exact Content-Length headers.

## 3. Architecture & Security Conclusions for the Real PDF Module

1. **Engine Selection Confirmed (ADR-5):**
   - EmbedPDF 2.15.1 meets all requirements for rendering, virtualized scrolling, search, text selection, and modular annotations. No fallback engine (e.g. PDF.js or native viewer) is needed.
2. **Annotation Storage Strategy (Spec §7.3):**
   - Retain original PDF immutability (`fileKey = sha256(pdf)`).
   - Offload stamp binary bytes (`ctx.data`) into `ProjectService.putFile(projectId, sha256(bytes), blob)`.
   - Store JSON manifest referencing `{ ...annotation, stampFileKey: sha256(bytes) }`.
   - Reconstruct `{ annotation, ctx: { data: buffer, mimeType } }` upon `importAnnotations()`.
3. **Save Trigger Event:**
   - Attach listener to `AnnotationScope.onAnnotationEvent`.
   - Debounce triggers by 1000 ms to batch multi-stroke drawings or property tweaks.
4. **Content Security Policy (CSP) Directives for PDF Module:**
   - `script-src 'self' 'wasm-unsafe-eval'`: Required by PDFium WASM engine for WebAssembly instantiation.
   - `connect-src 'self' blob: data:`: For local WASM and blob fetching.
   - `img-src 'self' blob: data:`: For rendering stamp images and canvas page previews.
   - No external CDN domains required.
