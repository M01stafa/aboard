## 3. Checks & Technical Findings

### Check 1: Google OAuth Sign-In & Token Isolation (VERIFY V06)
- **Result:** **PASS (Path A verified with session purge)**
- **Finding:**
  1. During Google OAuth sign-in with `scopes: "https://www.googleapis.com/auth/drive.file"`, the initial redirect provides `provider_refresh_token` in memory.
  2. The application posts `provider_refresh_token` to `drive-link-token` where it is encrypted with AES-256-GCM using `TOKEN_ENC_KEY` and saved in `google_drive_links`.
  3. The application immediately calls `supabase.auth.refreshSession()`.
  4. Inspection of `GoTrueClient._callRefreshToken`: Calling `refreshSession()` triggers `POST /auth/v1/token?grant_type=refresh_token` against GoTrue. The GoTrue server issues a new Supabase session without provider tokens.
  5. `GoTrueClient._saveSession` overwrites the stored session in `localStorage`.
  6. **Automated Storage Audit:** Verified that across `localStorage`, `sessionStorage`, and `IndexedDB`:
     - `provider_token`: ABSENT
     - `provider_refresh_token`: ABSENT
     - Google access token (`ya29.`): ABSENT
     - Google refresh token (`1//`): ABSENT
  7. **Conclusion:** Path A succeeds without token leakage. Switching to the server-only Path B fallback is **not required**.

### Check 2: Short-Lived Access Token & Folder Creation (VERIFY V08)
- **Result:** **PASS**
- **Finding:**
  - `drive-token` delivers a short-lived access token (`expires_at ≈ Date.now() + 3600_000`).
  - Creating project folder via `POST https://www.googleapis.com/drive/v3/files`:
    - Payload: `{ name: "Aboard (Spike S4 Test)", mimeType: "application/vnd.google-apps.folder", appProperties: { app: "aboard" } }`.
    - Returns HTTP 200 with folder `id`.

### Check 3: Multipart Small File Upload (VERIFY V08)
- **Result:** **PASS**
- **Finding:**
  - Executed via `POST https://www.googleapis.com/upload/drive/v3/files?uploadType=multipart`.
  - Content-Type: `multipart/related; boundary=-------aboardboundary123`.
  - Body carries JSON metadata part (`name`, `parents`, `appProperties`) and binary content part.
  - Successfully uploads files under 5 MB in a single round-trip.

### Check 4: 100 MB Resumable Upload & Header Inspection (VERIFY V08)
- **Result:** **PASS**
- **Finding:**
  - Initial session request:
    ```http
    POST /upload/drive/v3/files?uploadType=resumable HTTP/1.1
    Host: www.googleapis.com
    Authorization: Bearer <access_token>
    X-Upload-Content-Type: application/octet-stream
    X-Upload-Content-Length: 104857600
    ```
  - **Location Header Check:** Google Drive API responds with `Access-Control-Expose-Headers: Location, Range, ...` and returns `Location: https://www.googleapis.com/upload/drive/v3/files?uploadType=resumable&upload_id=...`. Browser client reads the `Location` header successfully.
  - **Chunk Upload & Range Header Check:**
    - Sending 8 MiB chunk: `PUT <session_url>` with `Content-Range: bytes 0-8388607/104857600`.
    - Google responds with HTTP `308 Resume Incomplete`.
    - `Range` header in response is exposed and readable (`Range: bytes=0-8388607`).
  - Proves resumable chunked uploads up to 100 MB work directly from the browser without proxying through our servers.

### Check 5: Google Picker Integration & Class Names (VERIFY V09)
- **Result:** **PASS**
- **Finding:**
  - Script loaded from: `https://apis.google.com/js/api.js`.
  - Loader invocation: `window.gapi.load("picker", { callback })`.
  - Builder instantiated with `NEXT_PUBLIC_GOOGLE_API_KEY`, `NEXT_PUBLIC_GOOGLE_APP_ID`, and short-lived access token.
  - View configured: `new google.picker.DocsView(google.picker.ViewId.DOCS).setMimeTypes("application/pdf")`.
  - DOM Inspection confirms current class names:
    - Root modal container: `.picker-dialog`
    - Modal backdrop: `.picker-dialog-bg`
    - Content frame / dialog: `.picker-modal-dialog`

## 4. Key Architectural Takeaways for Real Modules

1. **Token Hygiene Guaranteed:** The combination of `drive-link-token` + `supabase.auth.refreshSession()` completely purges `provider_refresh_token` and `provider_token` from browser storage while retaining an encrypted copy on the server.
2. **Drive Storage Layer Verified:**
   - Files < 5 MB use multipart uploads.
   - Files ≥ 5 MB use resumable chunked uploads in 8 MiB chunks.
   - Files are tagged with content hash in `appProperties.hash` for deduplication.
3. **No Fallback Needed:** Path A works reliably. Path B remains implemented as secondary connection/reconnection flow.
