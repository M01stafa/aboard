## 2. Checks & Findings

### Check 1: Toolchain Installation & GWT Compatibility
- **Result:** **PASS**
- **Findings:**
  - JDK 11 (`EclipseAdoptium.Temurin.11.JDK`) was installed via winget and verified with `java -version`.
  - Gradle 8.7 was installed from `https://services.gradle.org/distributions/gradle-8.7-bin.zip` and verified with `gradle -version`.
  - The GWT 2.8.2 toolchain compiled cleanly under JDK 11. Escalation to JDK 17 was not required.

### Check 2: Git Submodule Attachment
- **Result:** **PASS**
- **Findings:**
  - The public fork `https://github.com/M01stafa/circuitjs1.git` was successfully added as a Git submodule at `vendor/circuitjs1` with `.gitmodules` registered at the repository root.

### Check 3: GWT Build & Site Assembly (`compileGwt` and `makeSite`)
- **Result:** **PASS**
- **Findings:**
  - `gradle compileGwt` executed the GWT compiler against `com.lushprojects.circuitjs1.circuitjs1`, compiling 5 permutations into `vendor/circuitjs1/build/gwt/out/circuitjs1` in 1 minute 10 seconds.
  - `gradle makeSite` assembled all static assets (`circuitjs.html`, `canvas2svg.js`, `lz-string.min.js`, and compiled GWT artifacts) into `vendor/circuitjs1/site/`.
  - *Platform discovery:* The stock `makeSite` task in `build.gradle` included a `doLast` shell invocation of `ls -la` which failed on native Windows; replacing this with standard cross-platform execution allowed `makeSite` to complete with `BUILD SUCCESSFUL`.

### Check 4: Embed in Same-Origin Iframe in Next.js 16.4 App (`spikes/S2-circuit`)
- **Result:** **PASS**
- **Findings:**
  - The build output from `vendor/circuitjs1/site` was copied into `spikes/S2-circuit/public/circuit/` (466 total assets).
  - As required by spec §7.2, the `WEB-INF/` folder was strictly excluded from the web application's public folder.
  - Next.js 16.4 with React 19 and Turbopack loaded and built `spikes/S2-circuit` without errors or warnings.
  - Embedded in a same-origin iframe via:
    ```tsx
    <iframe id="circuit-iframe" src="/circuit/circuitjs.html?hideMenu=false&running=true" />
    ```

### Check 5: Attachment to `window.CircuitJS1` & Strict Mode Resilience (VERIFY V18)
- **Result:** **PASS**
- **Findings:**
  - `JSInterface.java` establishes `window.CircuitJS1` and triggers `window.oncircuitjsloaded(CircuitJS1)`.
  - In `app/page.tsx`, both immediate attachment (`if (win.CircuitJS1)`) and delayed attachment via `win.oncircuitjsloaded` were implemented.
  - Under React Strict Mode (`reactStrictMode: true`), the double-mount was verified: the unmount cleanup safely clears subscribers, and the second mount cleanly binds without throwing or creating duplicate listeners.

### Check 6: API Round-Trip (`exportCircuit`, `importCircuit`, `getCircuitAsSVG`) (VERIFY V18)
- **Result:** **PASS**
- **Findings:**
  - `exportCircuit()`: Invokes `app.dumpCircuit()`, returning the circuit text beginning with `$ <flags> <maxTimeStep> <simSpeed> ...`.
  - `importCircuit(text, subcircuitsOnly)`: Invokes `app.importCircuitFromText()`, correctly restoring elements. Re-exporting matches the original circuit text.
  - `getCircuitAsSVG()`: Invokes `app.imageExporter.doExportAsSVGFromAPI()`, which dynamically loads `canvas2svg.js` via `ScriptInjector` and invokes `window.CircuitJS1.onsvgrendered(sim, svg)`. The delivered SVG contains well-formed `<svg>...</svg>` XML.

### Check 7: Service Worker & Manifest Check (Stock Build)
- **Result:** **PASS (Finding Logged)**
- **Findings:**
  - Inspected `vendor/circuitjs1/war/circuitjs.html` lines 4 and 170–180:
    ```html
    <link rel="manifest" href="/circuit/manifest.json">
    ...
    <script>
    if ('serviceWorker' in navigator) {
      window.addEventListener('load', () => {
        navigator.serviceWorker.register('service-worker.js')...
      });
    }
    </script>
    ```
  - The stock build registers a service worker (`service-worker.js`) and links to `manifest.json`.
  - **Required Fork Patch 1:** In Phase 4 (Task 24), this block and `<link rel="manifest">` must be removed from `circuitjs.html` so that CircuitJS1 does not hijack the main application's service worker scope or caching.

### Check 8: Security Script-Execution Check (Security Rule §14.6)
- **Result:** **PASS**
- **Findings:**
  - Executed `grep -rn "eval(\|new Function\|\$wnd.eval" vendor/circuitjs1/src`.
  - Findings:
    - `new Function`: 0 occurrences.
    - `$wnd.eval`: 0 occurrences.
    - `eval(`: All matches reside within `com.lushprojects.circuitjs1.client.Expr` and `CCVSElm`, which implement mathematical expression evaluation for circuit components (`Expr.eval(ExprState)`).
    - Zero JavaScript `eval` or dynamic code execution exists in the fork sources.

### Check 9: Content Security Policy Directives (VERIFY V14 GWT part)
- **Result:** **PASS**
- **Identified Directives for `/circuit/:path*`:**
  - `script-src 'self' 'unsafe-inline' 'unsafe-eval'`: GWT permutation loaders and `canvas2svg.js` injection require inline execution; GWT deferred bindings require `'unsafe-eval'`.
  - `style-src 'self' 'unsafe-inline'`: Required for inline styles in `circuitjs.html` and dynamic GWT component styling.
  - `img-src 'self' data: blob:`: Required for canvas export buffers (`toDataUrl()`) and GWT UI icons (`clear.cache.gif`).
  - `font-src 'self' data:`: Required for `font/fontello.*` assets.
  - `connect-src 'self'`: Required for GWT permutation definitions (`compilation-mappings.txt`, `*.cache.js`, `locale_*.txt`, `setuplist.txt`).
  - `frame-src 'self' javascript:`: Required for GWT history support (`<iframe src="javascript:''" id="__gwt_historyFrame">`).
  - Parent application CSP: `frame-src 'self'` allows embedding `/circuit/circuitjs.html` in an iframe without cross-origin boundary issues.

## 3. Conclusion & Recommendations for Phase 4 (Circuit Module)

1. The build pipeline (`gradle compileGwt` + `gradle makeSite`) under JDK 11 and Gradle 8.7 is validated and reproducible.
2. The JavaScript API bridge (`exportCircuit`, `importCircuit`, `getCircuitAsSVG`, `onsvgrendered`) is functional and resilient to React Strict Mode double-mounting.
3. Keep `/circuit/:path*` isolated with dedicated CSP headers in `apps/web/next.config.ts` using the negative-lookahead pattern, so GWT's need for `'unsafe-eval'` never weakens the security of the main application.
4. Apply the planned fork patches (service worker removal, Arabic locale, and extended command interface) when implementing the real circuit module.
